# CorpusTrail agent guidance

Read `README.md`, then the **Current handover** in
`docs/developer/DEVELOPMENT_BUILDS.md` at the start of a task. Read the applicable
approved specification before implementation. Its status prose is historical;
explicit researcher acceptance entries determine checkpoint status.

Use the existing scientific services, versioned loopback API, packaged frontend
and browser acceptance harness. Preserve exact identity, immutable history,
evidence trust, method-blind response boundaries and explicit human authority.
No live scholarly/model requests, new dependency, paid operation, destructive
cleanup, release, main/tag change or separately gated integration without approval.
Use disposable synthetic projects; never inspect or migrate unrelated research.

At completion or interruption, update the same concise Current handover with
current work, outstanding issues, evidence links and explicit researcher decisions.
Keep delivered code/run/wheel identities separate from later documentation-only
commits. Do not create competing handovers or rebuild solely for a status update.
Preserve earlier checkpoint records. Do not edit the approved implementation plan.
Inspect repository state first; preserve unexpected edits. Never force agreement
with historical SHAs, autoapprove images or weaken tests to obtain green results.
Use existing standard public GitHub runners under the approved zero-cost boundary.

Agent-specific wrappers are unnecessary unless a real tool difference requires one.
This shared guidance applies to Codex, Claude Code and human contributors alike.

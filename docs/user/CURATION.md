# Curation and audits

Open **Curation and Audits** from the project dashboard. This is an operational,
not method-blind workspace. Manual Guided Review is always available without a
classifier. The normal launcher registers no assessment engine. Local embedding,
external LLM, typed decision and hybrid adapters are explicitly unavailable until
separately implemented, installed and validated. Synthetic browser examples test
software architecture, not relevance accuracy or real-model interoperability.

## Inspect the complete population

Choose a saved run. Its frozen population, reference version, evidence inputs,
policy, producer, execution state and calibration binding remain inspectable.
Include, exclude, uncertain, failed and not assessed are disjoint primary totals;
together they exhaust the frozen population. Evidence-sufficiency, disagreement
and human-review filters overlap those totals and each other: do not add them.
Likely exclusions, failures and unassessed papers remain accessible. There is no
automatic exclusion or stopping rule. Failure is not a scientific judgment.
Scores retain their declared scale and calibration state, not an assumed
probability. Comparing runs may also compare different evidence/reference inputs.

Inspect the exact frozen target and supplied reference passages separately from
the publication's current evidence. Reading a displayed passage does not attest
that a human read it. Full-set inputs and frozen bounded contexts use the same
CP8 evidence, self-match and held-out-label protections.

## Select and review an audit

Explicitly preview a random-within-filter or policy-stratified selection, naming
the actor, seed and sample size. Strata can include likely exclusions, uncertainty,
failures and unassessed candidates. Denominators and overlap are recorded.
Freeze saves the exact selection and source versions; it records no judgment.
Neither selected nor unsampled candidates disappear. A filtered/stratified audit
is not automatically an unbiased corpus-wide performance estimate.

Choose an explicit reviewer and confirm operational assistance to start human
review. Original engine observations remain separate and no answer, rationale or
reading extent is prefilled. Save records only a human observation. Finish
preserves it and leaves unassessed papers undecided. Only the existing separate,
authorized preview/confirmation action publishes corpus membership. Saved audit
outcomes distinguish observations from authorizations. Method-blind Review uses
separate API routes and does not expose these assisted sessions or proposals.

## Correct references, then explicitly request reassessment

Inspect the evidence and choose your own reference label, actor, rationale and
evidence actually used. Explicitly attest the correction. Preview shows the
proposed successor and superseded same-paper labels; commit appends a successor
reference version with exact run/result/audit lineage. The previous references,
contradictory source assignments and assessment runs remain unchanged.

Nothing is retrained, rerun or published by a correction. To reassess, explicitly
prepare a new plan, choose the successor version and desired frozen population,
inspect inherited policy/settings/validation roles, freeze the plan, request a
new run, then separately execute bounded work. Reusing corrected validation
labels does not establish fresh independent performance. Interrupted reservations
require explicit recovery; opening/restarting the application never resends work.

All lists are server-paginated. Later result pages reject changed run/human-status
revisions; restart pagination explicitly. Append-only history pages use a fixed
cutoff. An older project requires **Back Up and Enable Curation** before writes;
opening it alone does not upgrade it. Originals and earlier scientific history
are preserved. Project removal remains a separate, explicit operation.
